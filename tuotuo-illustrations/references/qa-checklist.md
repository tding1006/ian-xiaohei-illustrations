# QA Checklist

## 必过项

- 是 16:9 横版。
- 背景是干净白底。
- 有托托。
- 托托承担核心动作，不只是装饰。
- 托托的形象和 `assets/ip/tuotuo-mia.png` 一致：黑长发、墨绿长裙、黑短靴、黑颈圈、平涂墨绿大眼、平静表情。
- 画面只有黑 + 墨绿（外加白底），没有第三种彩色。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 画面怪诞、有创意、有意思。
- 简洁清爽，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读。
- 墨绿只用于裙子、主路径、箭头和关键强调。
- 淡墨绿只用于补充说明、反馈或系统状态。
- 原来该用红色标重点的地方，用黑色加粗、实心块、双线或叉号表达。

## 失败信号

出现以下情况，重生成或局部编辑：

- 左上角有“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- 托托画成日系可爱少女：腮红、闪亮眼、睫毛、精细发丝、萌笑、可爱姿势。
- 托托换装、加配饰，或比例变成 Q 版二头身。
- 托托被画成吉祥物、表情包、儿童卡通。
- 画面里出现了红、橙、蓝或任何第三种彩色。
- 托托只是站在旁边看，核心动作由某个物件或 mia 完成。
- mia 抢了主角，或者出现了两只以上的猫。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太死板，没有荒诞隐喻。
- 和 `assets/examples/` 里的旧案例构图过于相似。

## 迭代方法

- 太普通：让托托成为动作主体，加入一个奇怪但成立的隐喻，让物件比例或用途不对劲。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太可爱：强调 flat two-color ink、deadpan、blank serious expression、not cute、not anime、no blush、no glossy eyes。
- 太像小黑：把剪影式、可变形的画法去掉，改成有发型、有裙摆、有手脚的固定人形。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 太像旧案例：保留核心意思，换掉主物件和托托的动作。
- 色彩跑偏：只留墨绿和黑，其余压缩成黑白灰阶手绘。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 交付判断

高质量图应该让读者先觉得“有点怪”，然后 1 秒内看懂结构。

如果第一眼像教程页或少女插画，而不是白纸上的怪诞产品草图，就不合格。
